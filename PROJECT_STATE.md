## Current Architecture

* React/Vite SPA served through the FastAPI deployment.
* FastAPI + SQLAlchemy API with PostgreSQL production configuration and SQLite development fallback.
* Local filesystem blob storage behind a bounded storage adapter.
* Database-backed, single-consumer document task queue.
* Three isolated workflows: cabinet reports use the original project/photo APIs and generator; boost plans use `backend/app/boost/`, `boost_*`, `/api/boost`; cabinet plans use `backend/app/cabinet_plan/`, `cabinet_plan_*`, `/api/cabinet-plans`, and `frontend/src/features/cabinet-plan/`. Existing project data needs no migration or reassignment.
* The plan workflows share workbook reading, document blocks, OOXML packaging, validation and isolated Word finalization in `backend/app/document_common/`; boost compatibility exports preserve its v1 input contract. Login, blob/image storage, template registry and worker heartbeat remain shared. One Word worker polls all three queues round-robin and runs one task at a time.
* Deterministic Pillow/OOXML generation followed by isolated Microsoft Word COM finalization.
* Optional OpenAI-compatible AI advisory path; all core operations work without it.
